# [ZHMolPhase](http://zhaoserver.com.cn/ZHMolPhase/ZHMolPhase.html)

## 1. Overview of ZHMolPhase

**ZHMolPhase is a multiscale deep-learning framework for predicting protein phase-separation propensity and identifying candidate LLPS regions.**

**We also provide an online calculation server for convenient use:**
[Click to access the online server](http://zhaoserver.com.cn/ZHMolPhase/ZHMolPhase.html)

## 2. Installation and Environment Setup

### Prerequisites

* OS: Ubuntu 20.04 LTS
* Python >= 3.8 (tested on 3.8.12)
* GPU is optional for ZHMolPhase inference. CPU inference is supported, whereas GPU acceleration is recommended for ESM-2 embedding generation and model training.

### Installation Steps

Follow the steps below to set up the environment. The installation has been tested in a clean environment.

### Option 1: Recommended (conda environment file)

```bash
conda env create -f environment.yml
conda activate ZHMolPhase_env
```

### Option 2: Manual installation

```bash
conda create -n ZHMolPhase_env python=3.8.12 -c conda-forge
conda activate ZHMolPhase_env
```


## 3. ESM-2 Environment for Embedding Generation

ZHMolPhase uses residue-level protein language model embeddings generated by **ESM-2 esm2_t33_650M_UR50D**. The standard ZHMolPhase workflow only requires ESM-2 embeddings. ESMFold is not required.

We recommend creating a separate conda environment for ESM-2 embedding generation.

### CPU Environment

```bash
conda create -n esm2_env python=3.9 -y
conda activate esm2_env

pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install fair-esm numpy biopython requests
```

### GPU Environment

For GPU-based embedding generation, install a CUDA-compatible PyTorch version. For example, for CUDA 11.8:

```bash
conda create -n esm2_env python=3.9 -y
conda activate esm2_env

pip install torch --index-url https://download.pytorch.org/whl/cu118
pip install fair-esm numpy biopython requests
```

After installation, check whether PyTorch and ESM are available:

```bash
python -c "import torch, esm; print('torch:', torch.__version__); print('cuda available:', torch.cuda.is_available()); print('esm imported successfully')"
```

The ESM-2 checkpoint should be provided as a local file. In the commands below, replace `/path/to/esm2_t33_650M_UR50D.pt` with the actual path to the local ESM-2 model checkpoint.

## 4. Usage

Example input files are provided in the `example/` directory, including:

- FASTA files containing protein sequences
- PDB files containing protein structures
- Precomputed protein language model embeddings (pLM)

The pLM features are generated using **esm2_t33_650M_UR50D**
(https://huggingface.co/facebook/esm2_t33_650M_UR50D).

### Download Trained Model

Download the pre-trained 5-cv model weights from Zenodo:
https://zenodo.org/records/18335181

After downloading, extract the archive and place the model files in the same directory as specified by the `--ckpt_dir` argument.

### Prepare Input Files from UniProt IDs

Given a `name.txt` file containing one UniProt ID per line:

```text
P37840
Q96NC0
O75157
```

download the corresponding UniProt FASTA sequences:

```bash
python scripts/get_sequence.py name.txt sequence
```

download the corresponding AlphaFold-predicted PDB structures:

```bash
python scripts/get_pdb.py name.txt pdb
```

compute ESM-2 residue-level embeddings:

```bash
conda activate esm2_env

python scripts/compute_esm2.py \
  --names_txt name.txt \
  --fasta_dir sequence \
  --out_dir LLM \
  --model_path /path/to/esm2_t33_650M_UR50D.pt
```

This will generate the following input files for each protein listed in `name.txt`:

```text
sequence/P37840.fasta
pdb/P37840.pdb
LLM/P37840.rep_1280.npy
```

If users already have their own FASTA, PDB, and ESM-2 embedding files, they can skip this preparation step and directly organize the files using the same directory structure.

### Predict Phase-Separating Proteins

```bash
conda activate ZHMolPhase_env

python predict.py \
  --names_txt name.txt \
  --fasta_dir sequence \
  --pdb_dir pdb \
  --llm_dir LLM \
  --ckpt_dir ckpts \
  --out output/score.txt
```

For the provided example files, users can also run:

```bash
python predict.py \
  --names_txt name.txt \
  --fasta_dir example/sequence \
  --pdb_dir example/pdb \
  --llm_dir example/LLM \
  --ckpt_dir ckpts \
  --out example/output/score.txt
```

### Predict Key Regions

#### Step 1: Compute Residue-level Occlusion Scores

```bash
python residue_score.py \
  --names_txt name.txt \
  --fasta_dir example/sequence \
  --pdb_dir example/pdb \
  --llm_dir example/LLM \
  --ckpt_dir ckpts \
  --window 11 \
  --out_dir example/output/score
```

#### Step 2: Extract Predicted Key Regions

```bash
python get_key_region.py example/output/score/<protein_id>_occlusion.tsv example/output/score/<protein_id>.txt
```

where `<protein_id>` corresponds to the protein name specified in `name.txt`.

## 5. Key-region Interpretation

For residue-level interpretation, ZHMolPhase uses a sliding-window occlusion strategy. Each consecutive 11-residue window is masked in turn, and the change in predicted LLPS probability is calculated as:

```text
Delta score = full-sequence score - masked-sequence score
```

A high positive Delta score indicates that masking this local region strongly reduces the predicted LLPS propensity, suggesting that the region may contribute to phase-separation behavior. Candidate key-region seeds are selected from high-scoring residues, expanded locally, merged if overlapping, ranked by their average occlusion score, and reported as predicted key regions.

## 6. Reproducing the Independent Test-set Evaluation

An end-to-end reproduction script is provided in `scripts/reproduce_test/`. All required test-set lists and FASTA input files are already included in the repository.

After installing the `esm2_env` and `ZHMolPhase_env` Conda environments and downloading the trained ZHMolPhase checkpoints as described above, run:

```bash
bash scripts/reproduce_test/run_test_pipeline.sh \
    --esm2-model /path/to/esm2_t33_650M_UR50D.pt \
    --esm2-env esm2_env \
    --zhmolphase-env ZHMolPhase_env \
    --clean
```

The script reproduces the ZHMolPhase predictions and evaluation figures for the independent LLPS and non-LLPS test sets used in the manuscript. The final results are saved in:

```text
scripts/reproduce_test/output/
├── ZHMolPhase/
│   ├── LLPS_score.txt
│   └── non_LLPS_score.txt
└── figure/
```

### Threshold-dependent and Threshold-independent Metrics

For ZHMolPhase and most compared methods, a default threshold of 0.5 is used unless otherwise specified. 
- 0.3: a permissive threshold, which tends to increase recall but may reduce precision.
- 0.5: the default decision threshold used for the main threshold-dependent metrics.
- 0.7: a more stringent threshold, which emphasizes higher-confidence positive predictions.
- 0.9: a highly stringent threshold, used to examine performance when only very high-scoring proteins are classified as positives.
